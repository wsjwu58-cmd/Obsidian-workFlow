# Harness-R1：从智能体失败轨迹学习编辑可执行运行时 Harness

> arXiv:2608.02276（cs.AI，2026-08-03 提交）| 代码：[github.com/DeepExperience/Harness-R1](https://github.com/DeepExperience/Harness-R1) | 模型：[huggingface.co/ShaoShuai0605/Harness-R1](https://huggingface.co/ShaoShuai0605/Harness-R1)
> 作者：Shuai Shao、Kangning Zhang、Qingyao Li、Shijian Wang、Hao Wang、Wenxiang Jiao、Yuan Lu、Yi Guo、Weiwen Liu、Weinan Zhang

## 摘要

围绕大语言模型构建的智能体在部署过程中会不断积累交互轨迹，但其行为通常保持不变。除了更新模型权重之外，这些轨迹还可以改进智能体的 harness——即构造上下文、中介工具、校验动作并恢复执行的那一层。我们提出 Harness-R1，据我们所知，这是第一种把「基于失败、贯穿生命周期地编辑现有可执行运行时」变成可学习能力的方法。它用在线强化学习后训练一个专门的 harness 工程师，使其编辑以实际达成的任务成功为目标进行优化，而不是由固定编辑器提出。一个独立的 9B 工程师把一批批目标智能体的失败转换成经过验证的可执行补丁；对冻结目标做新鲜的同一批次重跑，为补丁提供结果奖励，因此训练只更新工程师。冷启动监督微调初始化该编辑策略，随后用群组相对策略优化（GRPO）在线训练。在 WebShop、ALFWorld 与 DBBench 上，Harness-R1 把 vanilla Qwen3.5-9B 的成功率从 44.3% 提升到 53.6%（+9.3 个百分点）。在对目标智能体直接微调之后，针对该目标训练的工程师再把平均值从 59.2% 进一步提到 64.2%（+5.0 个百分点）；由于这些提升在目标微调前后都成立，Harness-R1 指向了 harness 工程师与目标智能体的共同进化。

## 1 引言

大语言模型是工具型智能体的决策核心，使智能体能够理解任务、维护状态，并通过与外部环境的多轮交互追求复杂目标（[40](https://arxiv.org/abs/2608.02276)；[16](https://arxiv.org/abs/2608.02276)；[13](https://arxiv.org/abs/2608.02276)；[46](https://arxiv.org/abs/2608.02276)）。与单次模型调用不同，部署中的智能体会持续产生包含观察、动作、环境反馈与任务结果的轨迹。这些轨迹记录了成功经验，但也暴露了系统性失败，例如工具误用、状态丢失、协议违例、反复尝试与恢复失败。这引出一个自然的问题：智能体能否利用自身的交互经验持续改进，而不是部署后保持不变？这种「经验到改进」的闭环正是自进化智能体（self-evolving agents）的核心议题（[7](https://arxiv.org/abs/2608.02276)；[35](https://arxiv.org/abs/2608.02276)；[42](https://arxiv.org/abs/2608.02276)）。

智能体系统可以在两个互补的位置上改进。一条路线通过监督微调、强化学习或在线学习更新模型参数，直接改进做出任务决策的actor（[36](https://arxiv.org/abs/2608.02276)；[20](https://arxiv.org/abs/2608.02276)；[30](https://arxiv.org/abs/2608.02276)）。另一条路线保持模型固定，优化它周围的智能体 harness。上下文构造、记忆与技能、工具中介、动作校验，以及控制与恢复逻辑，都是 harness 的组成部分（[31](https://arxiv.org/abs/2608.02276)；[48](https://arxiv.org/abs/2608.02276)；[10](https://arxiv.org/abs/2608.02276)）。它们共同决定了模型看到什么、能执行哪些动作、如何解读环境反馈，以及执行偏离后如何恢复。因此，相同的模型权重在不同 harness 下可以产生截然不同的智能体能力。Harness 优化提供了一条与模型训练互补的路径：它改进模型与环境之间的运行时机制，而不改变模型本身。

直接修改 harness 并不总是可靠的。图 1 比较了三个基准上「匹配基线」的平均环境奖励变化。固定的 Self-Refine 规则（[22](https://arxiv.org/abs/2608.02276)）在三个基准上都降低了奖励；前沿模型作为 harness 编辑器的收益则不稳定或有限，有些甚至降低了 WebShop 的奖励。因此，提示强大但固定的模型去编辑 harness 还不够可靠。

**图 1：** 三个基准上匹配基线的奖励变化；菱形表示等权平均。

除了这类提示式编辑，近期系统构建了专门的 harness 优化流水线。Meta-Harness、Agentic Harness Engineering 与 AutoHarness 使用智能体式 proposer，基于 harness 状态、执行轨迹与任务反馈联合编辑提示词、工具、记忆、中间件或控制逻辑；Life-Harness 与 HarnessX 把可编辑面扩展到生命周期干预与类型化组件（[12](https://arxiv.org/abs/2608.02276)；[17](https://arxiv.org/abs/2608.02276)；[19](https://arxiv.org/abs/2608.02276)；[37](https://arxiv.org/abs/2608.02276)；[3](https://arxiv.org/abs/2608.02276)）。然而，harness proposer 通常保持固定：结果只用于选择或迭代精修补丁，不会直接更新 proposer 参数；HarnessX 用跨 harness 的 GRPO 训练任务模型，而 AEGIS 保留符号化的 harness 编辑。互补的工作优化提示词、示例、记忆、技能或任务求解程序（[38](https://arxiv.org/abs/2608.02276)；[11](https://arxiv.org/abs/2608.02276)；[31](https://arxiv.org/abs/2608.02276)；[48](https://arxiv.org/abs/2608.02276)；[36](https://arxiv.org/abs/2608.02276)；[20](https://arxiv.org/abs/2608.02276)；[30](https://arxiv.org/abs/2608.02276)），但通常只隔离单个工件，或构造新的求解程序。工作流可以是 harness 的一部分，但生成一个工作流，与学会把「失败条件化的可执行干预」安装进现有多阶段运行时，是两回事：后者必须从真实的目标智能体失败中决定何时干预，并协调上下文、状态、动作执行与恢复。这留下一个研究较少的问题：**我们能否用在线强化学习后训练一个专门的 harness 工程师，使「根据观察到的失败改进现有可执行运行时」变成一种可学习能力？**

直接训练 harness 工程师面临两个挑战。第一，可编辑运行时横跨相互依赖的执行阶段，不受限制的代码编辑可能破坏既有接口、产生不可执行的行为，或引入与任务成功无关的改动。第二，文本形式与静态规则无法判定补丁质量——只有补丁应用后目标智能体的行为才能判定。因此，训练需要一条有根据的反馈路径：从目标智能体的失败，经过受约束的可执行编辑，到更新工程师的性能增益。

我们提出 Harness-R1——一种训练范式：在保持目标智能体冻结的同时，用在线强化学习后训练一个专门的 harness 工程师。以批量的目标智能体失败为条件，工程师生成经过验证的可执行运行时补丁；打过补丁的目标重跑相同任务，实现的性能变化只奖励工程师。冷启动监督微调先初始化策略，再做在线 GRPO。跨 WebShop、ALFWorld 与 DBBench，Harness-R1 把 vanilla 目标的平均成功率从 44.3% 提到 53.6%（+9.3 个百分点），在直接目标微调后从 59.2% 提到 64.2%（+5.0 个百分点）。

主要贡献可总结如下：

- 我们把「失败条件化的、贯穿生命周期的 harness 编辑」形式化为一个专门工程师的在线强化学习问题，同时保持目标智能体冻结。
- 我们开发了 Harness-R1，把冷启动监督微调与「基于可执行运行时补丁实现效用」的群组相对策略优化结合起来，在三个交互基准上把 vanilla 目标提升了 9.3 个百分点。
- 我们证明 harness 工程师与目标智能体可以共同进化：在直接目标微调之后，目标专属的 Harness-R1 工程师再添 5.0 个百分点。

**图 2：** Harness-R1 概览。挖掘出的目标失败被整理成证据包（左）；harness 工程师写出一个可执行补丁，编辑冻结目标周围运行时中的四个生命周期点（右）；打补丁后的目标重跑相同任务，由此得到的同批次奖励只通过冷启动 SFT 与随后的 GRPO 训练工程师（底部循环）。方法、动作空间与生命周期钩子详见方法节。

## 2 相关工作

### 基于 LLM 的 Harness 演化

近期工作把智能体 harness 当作一个可执行的多组件优化对象。一条线从执行轨迹、评测分数与奖励中搜索或合成完整 harness：Meta-Harness 让一个编码智能体在先前候选中搜索，AutoHarness 从环境有效性反馈中迭代合成代码 harness，AHE 则联合演化提示词、工具、中间件、技能、子智能体与记忆（[12](https://arxiv.org/abs/2608.02276)；[19](https://arxiv.org/abs/2608.02276)；[17](https://arxiv.org/abs/2608.02276)）。另一条线把反复出现的交互失败变成跨多个执行阶段的、带回归检查的定点修复，把轨迹定位的诊断与回归感知的验证结合起来（[37](https://arxiv.org/abs/2608.02276)；[2](https://arxiv.org/abs/2608.02276)；[45](https://arxiv.org/abs/2608.02276)）。作为关系密切的同期方向，HarnessX 组合类型化处理器，用 AEGIS 做符号化的轨迹驱动适配，并对任务模型做跨 harness 的 GRPO（[3](https://arxiv.org/abs/2608.02276)）。在这些系统中，proposer 可以是更强的外部模型或目标模型本身，但**没有一个会用 harness 编辑的结果后训练 proposer 或编辑器的权重**；反馈引导的是程序搜索、候选选择、回归测试或产物晋升。Harness-R1 则把学习目标从「结果 harness」移到「编辑策略」：在线强化学习在冻结目标上根据补丁实现的实际效用，后训练一个专门的 harness 工程师。

### Harness 组件的算法优化

更宽泛的一条线在预先指定的编辑空间与搜索过程内优化提示词等模型外部产物。有些方法让 LLM 针对分数提出并搜索指令候选，如 APE 与 OPRO（[49](https://arxiv.org/abs/2608.02276)；[38](https://arxiv.org/abs/2608.02276)）；另一些方法形成自然语言「梯度」或文本反馈并将其传播去编辑提示词或代码，如 ProTeGi 与 TextGrad（[27](https://arxiv.org/abs/2608.02276)；[43](https://arxiv.org/abs/2608.02276)）。基于种群的方法如 EvoPrompt、Promptbreeder 与 GEPA 按适应度变异并选择提示词（[9](https://arxiv.org/abs/2608.02276)；[6](https://arxiv.org/abs/2608.02276)；[1](https://arxiv.org/abs/2608.02276)）；流水线编译器如 DSPy 与 MIPRO 把程序结构与模块参数分离，在指令与引导示例上搜索（[11](https://arxiv.org/abs/2608.02276)；[26](https://arxiv.org/abs/2608.02276)）。这些方法可以调用强 LLM 并维护历史、种群或学习到的代理，但它们通常不会用编辑结果后训练 proposer、reflector 或反向引擎；即便有些方法微调了任务模块，产物也是任务专属的工件或参数，而不是一个由编辑结果训练出来的专门 harness 编辑器策略。Harness-R1 则根据其补丁实现的实际执行效果训练编辑器，并修改现有目标智能体运行时的多个阶段。

### 可学习的 Harness 编辑器

更直接相关的工作会后训练那些编辑或控制模型外部结构的策略，但每一类要么限制编辑空间，要么把编辑与任务求解耦合在一起。有些方法在狭窄目标上从下游结果训练专用编辑器，例如独立的上下文字段或可修订的技能库（[4](https://arxiv.org/abs/2608.02276)；[33](https://arxiv.org/abs/2608.02276)；[14](https://arxiv.org/abs/2608.02276)），或者学习生成由冻结执行器运行的任务求解工作流（[15](https://arxiv.org/abs/2608.02276)；[24](https://arxiv.org/abs/2608.02276)；[47](https://arxiv.org/abs/2608.02276)）。更接近运行时 harness 的工作，有的在无强化学习或持久代码补丁的情况下指令微调观察与动作投影，有的在离线 RL 下从少数预定义结构动作中选择，还有的把 harness 编辑并入单个任务 actor 的动作空间（[34](https://arxiv.org/abs/2608.02276)；[41](https://arxiv.org/abs/2608.02276)；[21](https://arxiv.org/abs/2608.02276)）。相比之下，Harness-R1 把 harness 编辑隔离为一个独立的学习问题：把失败条件化的、贯穿生命周期的编辑，塑造成一个专门工程师的独立在线强化学习任务，从它可执行补丁实现的实际任务结果中训练，而目标智能体保持冻结。

## 3 方法

本节介绍 Harness-R1：一个在线、结果导向的框架，后训练一个专门的工程师去改进冻结目标智能体周围的可执行运行时。我们先把 harness 编辑形式化为一个「批量条件化」的学习问题，其中每次修改都通过重跑相同任务来评估；然后描述修改可以干预智能体生命周期的哪些位置，以及冷启动监督微调加 GRPO 如何学到编辑策略。图 2 总结了「失败 → 编辑 → 重跑」循环以及可训练工程师与冻结任务智能体之间的分离。

### 3.1 问题设定

设 A 为冻结的目标智能体（其模型连同周围的基础运行时），设 B={x_i}_{i=1..n} 为环境 E 中 n 个任务的一批。在一个回合内，智能体与环境进行多轮交互：每一轮它读取累计的历史与当前观察，其冻结策略提出一个动作。动作以环境原生接口表达：结构化工具或 API 调用与文本命令，例如 WebShop 中的搜索与点击、ALFWorld 中的导航与物体操作、DBBench 中的 SQL 查询。环境执行动作、返回下一观察，并在回合结束时给出结果奖励。我们要适配的组件是基础运行时：把展示给模型的上下文组装起来、把每个动作转发给环境、再把反馈回传给智能体的那段代码。这个周围运行时（而不是模型权重）正是 harness 编辑的对象。让未修改的智能体在整个批次上运行，得到基线轨迹 τ_i⁰ 与奖励 R_i⁰。一个确定性提取器只保留失败的回合，把它们的任务约束、精选的动作-观察片段、结果与必要的环境状态压缩成一个失败包 s_B。工程师 H_θ 只读一次这个包，生成一个批量条件化的可执行覆盖层（overlay）P；它既不解任务，也不参与 rollout。

覆盖层 P 把这个循环包装成四个生命周期点的可执行钩子，完全不碰智能体权重（图 2 右）：（i）**回合初始化**（episode initialization）建立起始上下文与回合状态；（ii）**决策前**（pre-decision）在智能体决策之前用检索到的指引与接口约束扩充上下文；（iii）**动作前**（pre-action）是一个运行时守卫，可以在动作到达环境之前对其规范化、改写或否决；（iv）**反馈后**（post-feedback）检查返回的观察，并在轨迹停滞时触发恢复。这些钩子只接触冻结策略周围的输入与输出，从不接触策略本身；补丁在安装前会被验证，无效补丁不产生任何效果。附录 C 给出了每个钩子的调用点与允许的返回效果。

验证通过后，覆盖层被安装，同一个冻结目标重跑 B 中的每个任务，包括原本成功的任务。记 R_i^P 为重跑奖励。定义整批性能差与工程师奖励为：

```
Δ_B(P) = (1/n) · Σ_{i=1..n} (R_i^P − R_i⁰)                     (1)
r(B, P) = Δ_B(P)  若补丁有效且完整；否则 r(B, P) = 0
```

编辑前后使用相同任务控制了任务组成，但定义了一个同批次的转导式（transductive）目标：实例内没有迭代式精修，批次间也没有持久化的补丁记忆。这个奖励不可微，并且只有在编辑改变了目标智能体行为之后才能观测到，因此无法直接优化。

### 3.2 结果导向的后训练

Harness-R1 分两阶段学习编辑策略：冷启动监督微调首先初始化一个「有效、可执行编辑」的先验；在线、结果导向的 GRPO 随后优化补丁应用到冻结目标上实现的任务效用。

#### 冷启动监督微调

我们先用基础 harness 运行冻结目标，从产生的失败轨迹构建编辑实例。教师实例与 RL 实例使用不相交的任务批次。一个强教师从紧凑的失败包 s_j 提出序列化的编辑响应 y_j^T；我们用冻结目标验证并评估解析出的覆盖层，每个失败包至多保留一个可执行、完整、不退化的响应。由此得到的数据集 D_SFT = {(s_j, y_j^T)} 通过教师强制的逐 token 预测初始化工程师：

```
L_SFT(θ) = − (1 / Σ_j |y_j^T|) · Σ_j Σ_{t=1..|y_j^T|} log H_θ(y_{j,t}^T | s_j, y_{j,<t}^T)    (2)
```

#### 结果导向的 GRPO

从监督策略出发，我们执行在线 GRPO（[29](https://arxiv.org/abs/2608.02276)），对每个失败包从当前策略采样 K=8 个候选补丁（算法 1 第 4–5 行）。每个候选被解析并验证成补丁（第 6 行）；每个有效补丁被独立安装，并通过在相同完整任务批次上重跑冻结目标来评估（第 7 行）；无效、无操作或不完整的评估在式 (1) 下获得零奖励（第 8 行）。对奖励 r_k = r(B, P_k)，设 μ_B 与 σ_B 为同一失败包生成的八个候选的经验均值与标准差，把奖励规范化为优势（第 10 行）：

```
Â_k = (r_k − μ_B) / σ_B                                              (3)
```

设 y_k = (y_{k,1}, …, y_{k,T_k}) 为解析成 P_k 的工程师响应，ρ_{k,t}(θ) = H_θ(y_{k,t} | s_B, y_{k,<t}) / H_{θ_old}(y_{k,t} | s_B, y_{k,<t})。序列级优势由响应所有 token 共享，工程师最大化 token 平均的裁剪代理目标：

```
g_{k,t}(θ) = min{ ρ_{k,t}·Â_k,  clip(ρ_{k,t}, 1−ε_ℓ, 1+ε_h)·Â_k }          (4)
```

其中 ℓ^tr_{k,t} 与 ℓ^ro_{k,t} 分别是训练引擎重算与 rollout 引擎记录的旧策略 token 对数概率；w_{k,t} = clip(exp(ℓ^tr_{k,t} − ℓ^ro_{k,t}), 0, 2) 是截断的重要性权重。WebShop 提供塑形环境奖励，而 ALFWorld 与 DBBench 提供二值成功；不添加格式有效性奖励，也没有显式 KL 损失。只有工程师参数 θ 被更新（第 12 行），外层循环在更新束上迭代，直到训练预算耗尽（第 2、13 行）。

### 4.1 实验设置

**基准。** WebShop（[39](https://arxiv.org/abs/2608.02276)）评测有根据的网页导航：智能体必须搜索、查看并购买一件满足自然语言要求的商品。ALFWorld（[32](https://arxiv.org/abs/2608.02276)）是文本具身环境，家务任务需要多步导航、物体操作、状态跟踪与恢复。DBBench（来自 AgentBench，[18](https://arxiv.org/abs/2608.02276)）是关系数据库环境，自然语言任务需要模式检查、结构化 SQL 查询、记录操作与结果验证。三者共同暴露了长程交互、动作执行与接口合规方面的互补性失败。

**目标智能体与对比。** 我们的主要目标是冻结的 Qwen3.5-9B 智能体（[28](https://arxiv.org/abs/2608.02276)）。为检验在改进 actor 本身之后 harness 适配是否仍然有用，我们还在对任务智能体直接 SFT 之后评估同一骨干。除主要目标外，我们进一步把训练好的工程师应用到一组训练中未见过目标模型上，检验跨模型迁移。我们把未修改目标与四组对比：固定提示式智能体策略（ReAct（[40](https://arxiv.org/abs/2608.02276)）、Self-Refine（[22](https://arxiv.org/abs/2608.02276)）、Reflection（[31](https://arxiv.org/abs/2608.02276)））；被提示为 harness 工程师的强前沿模型（Qwen3.5-397B、GLM-5.2、Kimi-K2.6、DeepSeek-V4-Pro、Gemini-3.5-Flash、GPT-5.5）（[28](https://arxiv.org/abs/2608.02276)；[44](https://arxiv.org/abs/2608.02276)；[23](https://arxiv.org/abs/2608.02276)；[5](https://arxiv.org/abs/2608.02276)；[8](https://arxiv.org/abs/2608.02276)；[25](https://arxiv.org/abs/2608.02276)）；仅监督的工程师；以及结果训练的 Harness-R1。在每个基准内，编辑器在**不安装其补丁**的情况下与同一目标和任务集对照评估。

**评测。** 三个基准都报告任务成功率，WebShop 另报塑形环境分数；成功率分别在 WebShop、ALFWorld、DBBench 的 500、500、300 个任务上计算。ALFWorld 额外报告六个任务族的成功率与任务级微平均（All），我们以三基准平均（Avg.）作为总体摘要。Reflection 在单独的「两回合 success@2」协议下报告：其成功列是两个回合的累计，Score 在重试第一回合失败后测量，而其他所有行报告 success@1，因此不与单回合方法排名比较。

**训练与选择。** 工程师是一个独立的 9B 模型，由冷启动 SFT 初始化，再在目标保持冻结时用在线 GRPO 优化。冷启动 SFT 集包含约 1000 个可执行编辑示例，由 GPT-5.5 教师提出并经冻结目标验证过滤；在线 GRPO 在来自不相交任务划分的约 1500 个失败包上训练。我们用聚合的开发性能选择检查点，所有训练变体使用同一个可执行补丁接口。附录 A 复现工程师提示词模板，附录 B 列出训练、解码与奖励超参数，附录 D 详述任务级 SFT、RL、验证与测试划分。

### 4.2 主结果

表 1 汇总了目标专属性能与提示式策略、前沿工程师和监督式工程师训练的对比。我们以任务成功率为主要指标。

**结果训练的 harness 编辑提升了冻结目标。** Harness-R1 在全部三个基准上提高了成功率，把等权平均从 44.3% 提升到 53.6%，增益 9.3 个百分点。绝对增益最大的是 ALFWorld，成功率从 40.6% 升到 53.2%；WebShop 与 DBBench 也都有提升。结果训练的工程师比仅监督的工程师高出 7.1 个百分点。

**专门的训练工程师比固定替代方案更有效。** 前沿工程师中最强的是 GLM-5.2，平均 48.8%，低于 Harness-R1 的 53.6%。提示式策略并非普遍有益：ReAct 把平均提升 3.2 个百分点，而 Self-Refine 使其降低 2.5 个百分点。Reflection 在其两回合协议下达 55.8% 的累计成功率，与单回合各列不可直接比较。

**harness 工程师与目标智能体共同进化。** 直接智能体 SFT 把未修改目标提到 59.2% 的平均，为这个更强 actor 训练的目标专属 Harness-R1 工程师再提到 64.2%，额外 5.0 个百分点。因此，即使 actor 本身被微调后，harness 编辑仍然持续改进目标，说明工程师可以与目标智能体共同进化，而不是在智能体变强后饱和。增益集中在任务成功率，尤其在 ALFWorld；虽然个别指标略有下降，Harness-R1 仍然提高了微调智能体的整体成功率。

我们检验稀疏失败能否产生改善未见任务的补丁。对每个基准与 seed，每个工程师从冻结的 Qwen3.5-9B 目标观察同样的 10 个失败，生成一个基准专属补丁，并把它应用到所有其他任务上。合并的留出集包含 WebShop、ALFWorld、DBBench 上的 1,270 个任务；我们在三个匹配 seed 上重复该协议。

图 4(a) 显示 Harness-R1 把合并留出成功率提升 8.9±1.5 个百分点，三个 seed 均为正。同一协议下，Qwen3.5-397B 与 DeepSeek-V4-Pro 分别给出 −4.3±2.5 与 −0.4±3.6 个百分点。差距不仅在均值：两个前沿工程师在 seed 间都横跨零（围绕负均值的 ±2.5 与 ±3.6 个百分点散布），在边际收益与可观回退之间摆动，而 Harness-R1 以更紧的 ±1.5 在每个 seed 上保持为正。把一把失败转换成广泛有用的编辑，是仅靠规模无法获得的能力，也是结果导向训练使其既更强又更一致的能力。附录 F 额外报告了多少个 seed-基准补丁安装了真实干预，以及相应的全划分变化。

## 5 讨论

当智能体开始改进其他智能体时，harness 编辑就成了一种「AI 改进 AI」。在这种场景下，仅仅看起来正确的编辑是不够的：一次编辑直接干预一个正在运行的可执行系统，因此它必须精确、可验证，并且对被修改的智能体真正有益。这正是 Harness-R1 从每个补丁实现的任务结果（而不是文本看起来是否合理）中学习的原因。

**训练专门的工程师胜过提示更大的模型。** 如引言所示，提示强大但固定的前沿模型编辑 harness 并不可靠：它们优化的是「貌似合理」，输出语法有效、看起来合理的编辑，但因为从不重跑目标，无法判断编辑是否真的提高了任务成功率，因此收益不稳定，有时甚至降低奖励。Harness-R1 则在每个补丁重跑结果上训练，学到真正有用而非仅仅貌似合理的编辑：一个有效、格式正确的补丁是必要条件而非充分条件，最终要紧的是重跑目标是否确认了任务增益。由于信号来自结果而非模型规模，按这种方式训练的 9B 工程师超过了规模大得多的前沿编辑器（GLM-5.2 48.8% 对 Harness-R1 53.6%）。附录 H 检查了存储的补丁及其运行时轨迹，包括一个前沿编辑器补丁：其貌似合理的诊断编译成了降低成功率的实际行为。

**失败条件化的学习胜过固定 harness 模式。** Self-Refine、Reflection、ReAct 这类固定、手工设计的 harness 策略常被假定对智能体普遍有帮助，但它们把一条手工规则均匀地套到每个任务上，既忽略具体目标的失败模式，也不关心某次干预是否真的有效。我们的结果表明这不可靠：固定 Self-Refine 规则在三个基准上都降低奖励（平均 2.6 个百分点），ReAct 只带来有限且不一致的收益。Harness-R1 则基于目标智能体观察到的失败生成编辑，并且只保留经重跑验证有助于的补丁，因此它的改进适配每个目标，而不是押注某条万能配方。这种适配性也体现在生命周期上：主导干预点随环境而异（WebShop 是动作前中介，ALFWorld 是反馈后恢复），固定策略无法自行选择。

**局限与未来工作。** 本文研究的是从 vanilla 目标到微调目标的单次适配，其中重训的工程师仍能改进更强的 actor。自然的扩展是把它迭代成多轮共同进化：交替更新目标智能体与 harness 工程师，使一方的收益不断重塑另一方的训练信号；这种交替如何收敛、能否带来复利式增益，是通向部署后持续改进的智能体的有前景方向。我们的奖励也来自同批次任务结果，这让训练有据可依，但也把信号绑定在用于挖掘失败的任务上。未来工作可以在奖励中加入留出性能，使编辑显式针对未见任务上的回退进行优化；再加推理效率项，让有用的补丁不以不必要的运行时成本为代价，使单一工程师能联合权衡效用、鲁棒性与成本。

## 6 结论

本文把「对可执行智能体 harness 做失败条件化的、贯穿生命周期的编辑」形式化为一个专门工程师的在线强化学习问题，同时保持目标智能体冻结。我们提出 Harness-R1：用冷启动监督微调初始化编辑策略，再用 GRPO 在线训练，使编辑以可执行运行时补丁实现的任务效用为目标进行优化，而不是由固定编辑器产出。在 WebShop、ALFWorld 与 DBBench 上，Harness-R1 改善了每个基准，把 vanilla Qwen3.5-9B 目标的平均成功率从 44.3% 提到 53.6%（+9.3 个百分点）；为直接微调目标重训的工程师再把它从 59.2% 提到 64.2%（+5.0 个百分点）。学到的编辑器还能泛化：它迁移到 20 个未见过的目标模型，每个都有正增益，并改善了 1,270 个留出任务。这些结果共同表明，harness 构造是一种可学习的能力，与权重更新互补，并让工程师与目标智能体共同进化。
