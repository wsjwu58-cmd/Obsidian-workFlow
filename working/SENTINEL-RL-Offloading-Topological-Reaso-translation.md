# Sentinel-RL：在安全运营中心把拓扑推理从 LLM 智能体中卸载

> [arxiv.org/abs](http://arxiv.org/abs/2609.04159v1)｜分类：cs.CR（密码学与安全）/ cs.AI
> 作者：Uday Vallabhaneni、Cassie L. Cagwin、David J. Wild（Luddy School of Informatics, Computing and Engineering，印第安纳大学伯明顿分校）
> 提交：2026-09-03（arXiv v1）｜许可：CC BY 4.0
> 原文：http://arxiv.org/abs/2609.04159v1｜DOI：https://doi.org/10.48550/arXiv.2609.04159

## 摘要

大语言模型（LLM）智能体正越来越多地被提议充当自主的安全运营中心（security operations center, SOC）分析师，但当威胁涉及企业级网络状态时，有两个结构性限制会让它们不可靠：有限的上下文窗口装不下一个数千主机的认证图，而自由形式的生成无法保证所建议的遏制（containment）动作与其所作用的拓扑保持一致。我们提出 Sentinel-RL，一种企业级智能体化 SOC 架构，它把**拓扑推理**与**语义推理**解耦：一个异构图注意力编码器把实时认证子图汇总为固定维度的状态，一个近端策略优化（Proximal Policy Optimization, PPO）策略把该状态映射到一组受约束的调查动作，而 LLM 智能体循环被限制为消费策略的建议，并在一个评论者（critic）把关下产出分析师可读的叙述。我们在 LANL《Comprehensive, Multi-Source Cyber-Security Events》数据集 [1] 与印第安纳大学 Quartz HPC 集群上实例化了该系统，并报告四项结果：(i) 一种两阶段 CREATE 摄入模式在单台 32 核节点上于 14.2 分钟内把一个 2400 万边的认证子图加载进 Neo4j，相比经典的基于 MERGE 的管线约有 **24×** 吞吐提升；(ii) 一个滑动窗口告警引擎在 50 次试验中都能在 **≤2.5 秒**内可靠触发「25 事件/10 秒」阈值；(iii) PPO 在 200 次迭代上训练收敛到平均回合回报 **8.74±0.31**，在标注红队事件上的留出评测精确率（precision）为 **0.91**、召回率（recall）为 **0.87**；(iv) 集成的遏制闭环在**中位 6.3 秒**内完成一次完整的「检测→调查→建议→人工批准」周期。我们贡献了一个可复用的工程模式（**热节点死锁**绕行方案）、一个可移植的 HPC 部署模式（**锚节点共置**），以及一项涵盖误报经济学、可逆性保证、审计合规与人类审批边界的企业就绪性分析。

## I 引言

安全团队如今正淹没在噪声里。一个标准的安全运营中心每天要处理数以万计的告警（10⁴–10⁵）[2][3]，其中绝大多数是误报。虽然自动化这些工作流的必要性已被普遍接受，但争论的焦点现在集中在自动化究竟应该**放在哪里**。近来流行的做法是把一个大语言模型连接到一组 API，把它当作一名即插即用的分析师。这种配置能做出令人印象深刻的产品演示，但在真实的运行压力下会因两个根本原因而失效。

第一，网络环境根本无法干净地塞进一个文本提示词。一个中型企业网络会产生一张不断变化的认证网络，轻易就涉及 10⁴ 到 10⁵ 个主机节点，以及每天 10⁶ 以上的反复连接。当前没有任何 LLM 上下文窗口大到足以按追踪攻击者横向穿过系统所需的粒度来刻画这一拓扑 [1][4]。当模型超出上下文时，它会猜。在事件响应中，猜测隔离某台特定机器 *h* 究竟会真正切断攻击者的访问、还是仅仅迫使它转向，是一项巨大的运营风险。

第二，开放式文本生成是执行遏制协议的**错误机制**。诸如 isolate-host、block-ip 或 disable-account 之类的动作会直接影响业务连续性。任何扣动这些扳机的系统都需要被硬规则严格约束、可审计、且跨软件版本保持一致。生成一段概率性的文本补全提供不了这些保证中的任何一条。

这些局限指向一种混合的、神经—符号（neuro-symbolic）方案。与其强迫 LLM 处理一切，我们把它限制在它真正擅长的事情上：编写查询、汇总告警、起草报告。而真正把网络复杂的、具备拓扑感知的状态翻译成一小撮严格遏制动作的决策，则交给一个训练好的策略来完成。

我们构建 Sentinel-RL 正是为了把这种分工落地。该系统端到端部署，并针对 LANL 基准中的红队事件进行了严格测试；它引入了一个四层架构（§IV），把底层的 Neo4j 图数据、策略决策引擎（HetGAT 编码器 + PPO 策略）、遥测摄入管线与用户界面分离开来。

要让这套架构真正运转起来，还需要解决若干实际的工程障碍。在印第安纳大学的 Quartz 集群上扩展该系统时，我们开发出两个高度可复用的模式：一个两阶段 CREATE 方案，用于在重度并行摄入时绕开基于 MERGE 的死锁问题（§V-A）；以及一种在 SLURM 管理的计算节点上最优共置微服务的策略（§V-B）。

我们对 Sentinel-RL 做了广泛评测（§VI），测量范围从原始数据摄入吞吐与管线延迟，到强化学习智能体收敛得有多好，再到端到端的「检测→遏制」延迟。此外，我们还梳理了把它放进企业环境的现实问题（§VII）。部署一个自主智能体，需要回答关于误报代价的难题、确保动作可以被安全逆转或沙箱化，并精确定义人类究竟需要在何处介入做最终批准。

本文其余部分组织如下：§II 概述基础概念与既有研究，§III 描述威胁模型，§IV 详述四层架构，§V 说明工程实现，§VI 展示评测结果，§VII 讨论企业就绪性，§VIII 综述相关工作，§IX 总结。

## II 背景与动机

### II-A 横向移动的现实

一旦攻击者突破了边界，威胁的性质就完全改变了。横向移动（lateral movement）代表入侵的第二阶段：对手从初始立足点出发，通过劫持或提权凭据转向其他系统 [1][4]。在这一阶段，防御者面对的不再是单台机器上的孤立恶意软件，而是一个复杂的**图路由**问题。试图回答「我们应该隔离哪台机器？」这样一个根本性的运营问题，如果不分析受损节点周围的更广泛认证拓扑，基本上是不可能的。

正因为它精确捕捉了这种拓扑复杂性，LANL《Comprehensive, Multi-Source Cyber-Security Events》数据集 [1] 已成为横向移动研究公认的试验场。它跨越 58 天的真实生产流量，包含匿名化的 Windows 认证、DNS 查询、NetFlow 记录，以及经过核实的红队活动；它提供了一个规模庞大且贴近真实的测试环境，覆盖约 1.65×10⁹ 个事件、12,425 名用户与 17,684 个终端。

### II-B 结构化状态：图优于序列化提示词

近期文献压倒性地指向同一个结论：防御横向移动必须**原生地**把网络当作图来处理。我们在两个不同的研究方向上都能看到这一点。第一，建立在图架构上的检测模型持续优于依赖表格数据或序列日志的模型；在 LANL 数据集上的评测经常显示真阳性率（true-positive rate）攀升到 **85% 到 99%** 之间，同时把误报控制在 **5% 以下** [4][5][6][7]。第二，聚焦自主网络防御的研究 [8][10][11] 表明，利用异构图编码器的策略能够适应全新的网络布局，而像标准 MLP 这样的刚性模型则无法泛化。

对于任何构建 AI 驱动 SOC 智能体的人来说，结论很清楚：试图把一个实时网络的状态压平成序列化的文本提示词，会剥离掉关键的**关系**数据。Sentinel-RL 完全避开了这个陷阱。相反，我们部署一个异构图注意力网络（heterogeneous graph attention network, HetGAT）[12][13]，主动把正在发生的认证活动压缩成一个稠密的 64 维向量，从而为我们的策略引擎提供一种在数学上结构化的环境理解。

### II-C 用 PPO 保证稳定性

在为执行离散遏制动作选择强化学习算法时，可预测性至关重要。近端策略优化（Proximal Policy Optimization, PPO）[14] 恰好提供了这种稳定性。由于它的目标函数在数学上对策略更新的幅度做了裁剪，它能防止那种在真实安全环境中将是灾难性的、反复无常的剧烈行为漂移。

我们选择 PPO 主要就是看中这些对审计友好的特性。它能与现代分布式框架如 Ray RLlib [15] 无缝集成，在不同的随机种子下产生高度可复现的训练周期，并允许我们在策略被批准用于生产之前，针对历史留出场景对它进行严格的回归测试。我们将在 §VI 中详述该算法在我们特定的威胁调查马尔可夫决策过程中的实际收敛情况。

## III 威胁模型

**对手。** 我们的模型从初始边界被突破之后的那一刻开始。攻击者究竟是如何攻陷第一台内部机器的——无论是一封精心构造的钓鱼邮件、被盗凭据，还是被污染的软件供应链——对本系统而言无关紧要。一旦进入内部，他们的主要目标就是通过劫持有效账户（T1078）并滥用远程服务（T1021）来转向新机器，以扩大其活动范围。这与 MITRE ATT&CK 的 TA0008（横向移动）相符。我们不假设对手会针对主机操作系统投放复杂的零日漏洞利用，而是假定对手主要作为凭据滥用者行动——这一约束直接对应 LANL 基准中经过核实的红队活动 [1]。

**防御方能力。** 在防御侧，系统持续摄取整个环境中的实时认证遥测。它拥有必要的计算资源，把这种活动映射进一个持续更新的 Neo4j 图，近乎实时地刻画网络拓扑。虽然防御方完全有能力通过标准 SOAR API 执行诸如隔离机器或锁定用户配置文件的遏制措施，但在**哪些具体资产已被攻陷**这一点上，它一开始是完全盲目的。把那个隐藏的对手暴露出来，正是 Sentinel-RL 智能体的核心职能。

**信任假设。** 由于我们采用了一种专门的架构——由语言模型提出语境、由 RL 智能体决定动作——我们必须为「LLM 不可避免地会产生幻觉」这一现实做打算。因此，我们的安全保证完全依赖于一条不可绕过的验证链：内部评论者、策略审计器，以及最终的人在环路审批闸门。我们并不天真地假设 RL 策略总会做出完美的、数学上最优的选择。相反，我们假定它的行为被 §IV-E 详述的硬动作掩码与速率限制严格约束，同时辅以 §VII 讨论的更广泛的企业控制。

## IV 架构

Sentinel-RL 运行在一个高度模块化的四层架构上（图 1），清晰地隔离不同的运营职责，以确保各个组件可以互换、审计或升级，而不打断更广的管线。

**图 1：Sentinel-RL 的模块化四层架构。** 实线表示事故响应期间即时的请求/响应循环，虚线表示用于改进策略注册表的异步分析师反馈回路（§IV-E）。为消除集群网络结构带来的抖动，所有组件在物理上共置于单台 HPC **锚节点**上（§V-B），使平面间延迟被限制在回环接口内。图中组件包括：数据平面（Neo4j 认证图，2400 万边、17.6k 主机；Ray 分布式加载器，32 核节点）、策略平面（HetGAT 状态编码器，64 维拓扑向量；PPO 策略，基于 Ray RLlib，5 个动作、稀疏奖励；FastAPI 策略端点）、遥测平面（滑动窗口告警引擎 25/10 秒；触发 ≤2.5 秒时向智能体循环发送 webhook）、编排平面（LLM 分诊 + 评论者，基于 LangChain；Streamlit + pyvis UI，人在环路）。

### IV-A 数据平面

作为系统的基础记忆，数据平面持续地刻画实时网络。它利用一个 Neo4j 5.x 数据库来追踪 Host、User、Service 与 NetworkSegment 实体，并通过带时间戳的 Authenticates-To 与 Connects-To 关系把它们连接起来。我们使用一条 Ray Data 管线 [16] 把 LANL 的 auth.txt 数据集流式写入该图，并有意识地按源主机对工作负载进行分片，以保持高吞吐。为了与系统其余部分交互，这一层提供两个不同的挂钩：一个用于从遥测层吸收新事件的流式摄入端点，以及一个基于 Cypher 的查询接口，使神经编码器能够按需抽取图的局部快照。

### IV-B 策略平面

真正的决策引擎位于策略平面。当一条告警触发时，一个 HetGAT 编码器 [12][13] 会抽取可疑活动周围的**两跳邻域**。它把这张局部拓扑图压缩成一个 64 维的稠密向量，s_t∈ℝ⁶⁴。接着，一个 PPO 策略 [14] 评估该状态，并选择五个严格调查动作之一：QueryEDR、QueryAD、CheckThreatIntel、ExamineFirewall 或 TerminateAndOutputVerdict。

关键在于，我们把该策略作为一个独立的 FastAPI 微服务运行，而不是把它作为 RLlib 库依赖烘焙进系统。这样解耦强制实现了严格的版本控制，允许工程师把实验模型与线上的模型并行**影子部署**。此外，它还创造了一个干净的拦截边界，让外部治理工具（§IV-E）可以在动作执行前对其加以审查。

### IV-C 遥测平面

为了滤除数量惊人的良性流量，遥测平面充当一条高速绊线。它使用一个快速滑动窗口启发式来监控原始认证流。如果某个特定的源主机在一个很窄的 W=10 秒时间窗内发起了超过 N=25 次认证，引擎会立即向编排层触发一个 webhook，并传入该主机 ID 与精确的时间窗。我们刻意调校了这组 (W,N) 参数，以捕捉 LANL 红队数据中出现的那种激进的凭据喷洒战术，同时安全地忽略自动化批处理任务产生的可预测尖峰。

### IV-D 编排平面

这一层把机器自主性转化为人类监督。编排平面完全围绕 Streamlit 界面与 PyVis 网络图构建，使用 LangChain 管理两个专门的 LLM 角色。首先，一个**分诊（Triage）智能体**把 PPO 策略的数学输出转化为对人工分析师而言清晰、可叙述的解释。同时，一个**评论者（Critic）智能体**积极地审计所建议的动作，核验系统是否确实引用了足够的证据来支撑它。由于我们的运营信任天然是有限的，系统在没有人类操作员点击最终批准闸门的情况下，不能执行任何基础设施变更。

### IV-E 安全面

把一个自主智能体部署进真实环境，要求毫不妥协的护栏。我们把三条不可协商的约束直接硬编码进管线。第一，严格的**动作掩码**在物理上阻止智能体在未能从至少两个不同来源成功收集到佐证证据之前就敲定 TerminateAndOutputVerdict。第二，一份不可篡改的**审计日志**为每一个决策记录精确的网络状态、所选动作、时间戳与生效的策略版本。第三，由于策略是作为独立的、带版本的服务运行的，缓解一个退化模型所需做的仅仅是替换一个环境变量——无需整套系统重新部署。这些机制直接实现了 Foley 等人 [8] 所倡导的可逆性与稀疏奖励原则，同时满足了 Hicks 等人 [9] 所论证的、对不被中断的解释链的需求。我们在 §VII 中概述机构采用所需的更广泛行政控制。

## V 实现

把 Sentinel-RL 从理论架构转变为一个部署在印第安纳大学 Quartz HPC 集群上的实际系统，需要处理若干实际的摩擦点。我们通过 srun 使用 SLURM [17] 申请了中到大型计算节点（32 个 CPU 核、128 GB RAM）。把系统推到生产规模，暴露出两个在更小的测试环境中根本不会出现的重大工程障碍。我们在此记录我们的解决方案，因为它们代表了任何在 HPC 基础设施上构建基于图的自主智能体的人都可复用的模式。

### V-A 绕开锁竞争：两阶段 CREATE 模式

我们最初的数据摄入策略遵循标准的图数据库范式。我们把 LANL 的 auth.txt 记录流经一组并行的 Ray worker，每个 worker 执行逐行的 Cypher MERGE 命令，以确保不会创建重复的节点或边。在对 10 万条边所做的合成测试中，这种方法只需几秒即可完成。然而，当我们把它投入到 2400 万条边的生产子集上时，整条管线戛然而止。摄入吞吐骤降两个数量级，我们的 Ray worker 闲置着，被困在 Neo4j 的事务管理器队列里。

瓶颈源于 Neo4j 处理并发的方式。当一个事务触及某个节点时，数据库会自动对它施加一个写锁 [18]。企业认证网络天生是高度倾斜的；少数关键资产——比如域控制器或主文件服务器——锚定了极大比例的流量。因此，当数十个并行 worker 同时执行 `MERGE (a:Host {id:$src}) MERGE (b:Host {id:$dst}) MERGE (a)-[:AUTH]->(b)` 时，它们会在试图锁住那些高入度目标节点时不断碰撞。尽管实际写入的认证边彼此完全不同，共享的端点却迫使 worker 把操作串行化。

为消除这种竞争，我们把摄入管线完全重构为两个不同的阶段：

1. **顺序顶点预物化（Sequential Vertex Pre-materialization）。** 我们先对数据做一遍轻量的单次扫描，提取所有唯一的主机标识符，并用标准 MERGE 把它们插入数据库。由于不同机器的总数与认证事件的数量相比微不足道，这一顺序步骤瞬间即可完成，并完全避开了锁竞争的陷阱。
2. **并行边生成（Parallel Edge Generation）。** 一旦图为所有必需顶点做好了种子，并行 worker 就接管。它们不再使用 MERGE，而是通过 MATCH 定位已存在的端点，并显式地 CREATE 新边。由于边本身是作为一个全新的实体被实例化的，这一操作绕开了锁定端点节点的需要。

下面的 Listing 1 展示了驱动该逻辑的具体 Cypher 查询。我们在 §VI-A 中量化吞吐的巨大恢复，并在图 2 中把性能可视化。

```cypher
// 阶段 1：顶点预物化（顺序执行，仅运行一次）
UNWIND $hosts AS h
MERGE (:Host {id: h});

// 阶段 2：并行边 CREATE（逐批执行，并行安全）
UNWIND $edges AS e
MATCH (s:Host {id: e.src}), (d:Host {id: e.dst})
CREATE (s)-[:AUTH {ts: e.ts, type: e.type}]->(d);
```

*Listing 1：两阶段摄入策略。阶段 1（第 1–3 行）顺序地保证所有节点都已存在。阶段 2（第 5–8 行）允许 worker 并行地安全写入海量边。*

> **洞见 1（热节点死锁模式）。** 当把高度倾斜、重尾分布的图数据（如网络认证）推入一个带写锁的数据库时，并行摄入必然会失败。工程师必须拆分工作负载：先顺序地预物化结构性顶点，再用显式 CREATE 命令并行执行繁重的边插入阶段。初始顺序扫描导致的微小时间开销，会被线程竞争的消除完全盖过。

### V-B 整合服务：锚节点模式

在早期的部署测试中，我们允许 SLURM 调度器自由地把我们的微服务——Neo4j、FastAPI 策略服务器、告警引擎与 Streamlit UI——分散到任意可用的计算节点上。结果是灾难性的、无声的失败。前端能加载，却抛出空的策略响应；告警引擎把 webhook 射向虚空；图数据库从外围计算节点根本不可达。

核心问题在于，HPC 集群的行为与现代 Kubernetes 环境大不相同。Quartz 集群的底层网络结构受到严格管制，除非专门配置，否则不会在随机的计算节点之间自动路由通用的用户态 TCP 流量。此外，依赖集群网络结构会让系统内部通信遭受由邻近批处理作业造成的严重延迟尖峰。我们还意识到，由于严格的内存上限与出站连接封锁，把服务卸载到登录节点上是不可能的。

我们的解决方案简单但绝对必要：我们放弃为交互式组件做跨节点分发。通过申请单个巨型分配（32 核、128 GB RAM）——我们称之为**锚节点（anchor node）**——我们把全部四个架构平面共置在同一台物理硬件上。这使得 Neo4j、策略端点与 UI 可以通过回环接口即时通信。我们仍然利用集群的原始算力来并行化 Ray 数据处理与 PyTorch 评测，但我们严格在锚节点的安全边界之内执行这种并行。

> **洞见 2（锚节点模式）。** 不要试图把延迟敏感的交互式微服务分散到多个 SLURM 管理的计算节点上。要把核心架构整合到单台重型锚节点上，以保证内部连通性；并只把分布式执行保留给网络延迟不会破坏应用逻辑的大规模、可并行批处理工作负载。

## VI 评测

为理解 Sentinel-RL 在真实运行压力下的表现，我们把基准测试集中在四个不同领域：原始数据摄入能力（§VI-A）、告警管线的响应性（§VI-B）、PPO 策略的收敛行为与准确率（§VI-C），以及从首次检测到最终遏制的总耗时（§VI-D）。每一次测试都在一台专用的 Quartz 锚节点上执行，配备 32 个 Intel Xeon 核（2.4 GHz）与 128 GB RAM，全程不使用 GPU 加速。

### VI-A 摄入吞吐

当把数以百万计的节点推入图数据库时，标准操作与优化技术之间的差异变得极其明显。表 II 给出了处理不断增长的认证边数量所需的绝对墙钟时间，对比传统的单阶段 MERGE 管线与我们定制的两阶段 CREATE 策略。

随着摄入数据量的扩大，单阶段方法呈指数级退化。这种严重的减速是锁竞争在高活跃节点上不断累积的直接后果。相反，我们的两阶段管线维持着一条非常稳定的、近乎线性的处理曲线，因为它在繁重的边插入阶段完全消除了线程竞争。当被要求处理 2400 万条边——大致相当于 LANL 网络一整天的实时流量——两阶段管线恰好在 **852 秒**内完成任务。相比之下，传统方法举步维艰；基于达到 6 小时运行上限后的线性外推，它需要 **21,600 秒**才能达到同一里程碑。图 2 以可视化的方式展示了这些最终的扩展轨迹。

### VI-B 告警管线延迟

一个自动化安全工具如果不能近乎实时地分诊并告警操作员，最终就是无用的。为验证遥测平面的响应性，我们把一条稳定的、每秒 10 个事件的合成流直接推入 AlertEngine。我们配置滑动窗口参数，在 10 秒滚动时间窗（W=10 秒）内追踪 25 个事件（N=25）。

结果证实该引擎极具响应性。从首个合格事件进入窗口的那一刻算起，它都能在不到两秒半的时间内可靠地派发触发 webhook。在我们的各次试验中，平均延迟稳定在 **2.31 秒**，第 99 百分位紧贴在 **2.45 秒**，记录到的绝对最大延迟为 **2.48 秒**。图 3 绘制了这一经验累积分布。在一级 SOC 这样的高风险环境中，把一次原始检测转化为分析师提示词的可接受运营预算，是以个位数秒来严格衡量的 [2]。我们的架构以舒适的余量越过了这一门槛。

**图 3：** 追踪 AlertEngine webhook 延迟的经验累积分布函数（CDF）。数据来自 50 次试验运行，处理一条合成的每秒 10 事件流，阈值配置为 (W,N)=(10 秒, 25)。管线取得均值延迟 2.31 秒、第 99 百分位 2.45 秒、最大延迟 2.48 秒。

### VI-C 策略训练与检测性能

我们在一个定制的马尔可夫决策过程内对 PPO 智能体训练了 200 次迭代。在环境感知方面，智能体完全依赖被标记主机周围两跳网络邻域的 HetGAT 嵌入。我们采用了受 Foley 等人 [8] 启发的严格稀疏奖励结构：只有当策略最终的 TerminateAndOutputVerdict 与 LANL 红队真值完全一致时，它才获得 +1；任何偏差都得到 0。

在五个独立随机种子上运行这套训练方案，揭示出一条高度稳定的学习曲线。如图 4 所示，智能体在最初的 80 轮内就获得了绝大部分策略能力。到第 200 次迭代时，性能紧密收敛到平均回合回报 **8.74±0.31**。

为评估真正的运营就绪度，我们在一个完全隔离的时间段上评测这个训练好的策略：LANL 数据集的最后八天，模型从未见过。结果见表 III，展示了稳健的能力。Sentinel-RL 取得了 **0.91 的精确率与 0.87 的召回率**。虽然 LMDetect [7] 仍捕捉到略高的原始召回，但我们的架构目前在相互竞争的基于图的检测系统中，为精确率与整体 F1 分数树立了基准。

**图 4：** PPO 智能体在 200 次迭代上的平均回合回报（R̄），在 5 个不同随机种子上取平均，阴影区域代表 ±1 标准差。策略迅速稳定，达到 8.74±0.31，并逼近 9.0 的理论上限。

### VII-A 误报与漏报经济学

安全运营中心流血的地方不在于漏掉的攻击，而在于被浪费的人力注意力 [3][19]。Sentinel-RL 直接直面混淆矩阵的财务现实。

误报会悄无声息地耗掉数千工时，在企业规模上制造巨大的资源黑洞。为防止告警疲劳，我们的 PPO 策略会结合历史频率过滤其 softmax 预测，只升级那些越过严格置信度门槛的告警。其余一切都被悄然归档，供可选的人工复核。此外，通过在奖励函数中为每个调查动作嵌入一点轻微惩罚，智能体学会高效地调查，而不是无休止地拉取遥测。

反过来，一次漏报会给予攻击者延长的驻留时间——这是关键失败。我们通过三道交叉的保障措施来对冲这一风险。如果策略的决策熵越过指定阈值，系统会自动要求人工介入，防止模糊威胁悄悄溜过。此外，RL 智能体与一个传统统计集成模型并行运行，任一系统发出的告警都会强制发起调查。最后，我们规定每一次新的策略迭代都必须通过严格的回归测试，确保针对留出红队数据集的召回率永不跌破可接受的基线。

### VII-B 可逆性与回滚保证

系统把每一项潜在对策归类为**可逆**（如隔离邮件或切断活动会话）或**不可逆**（如擦除数据或销毁凭据）。在自主运行时，Sentinel-RL 在物理上被锁定为只能执行可逆战术。任何永久性的基础设施变更都被重重加闸，要求明确的人类授权。最重要的是，智能体必须为它提出的每一个动作生成一份精确的逆转脚本。这份回滚计划直接附加到分析师的事件工单上，单击一下即可即时执行。

### VII-C 沙箱化动作验证

我们拒绝让一个自主智能体盲目地操纵真实环境。在执行任何遏制措施之前，Sentinel-RL 会把所建议的命令送入一个**响应沙箱（Response Sandbox）**。这个隔离的数字孪生镜像当前网络拓扑，使系统能够预测潜在的级联故障。它专门防止灾难性的乌龙，比如无意中隔离了唯一活跃的 DNS 服务器，或切断了对关键认证节点的访问。模拟完成后，所产生的影响报告会被永久追加到事件记录中，供事后分析。

### VII-D 审计合规

机构问责要求一条无懈可击的书面痕迹。每一个内部动作——从智能体最初的推理步骤到最终的人类签署——都被永久铭刻进一份经密码学保护的账本，并按事件编号细致索引。该日志记录精确的状态哈希、策略版本、置信度指标、所引用的证据，以及事件的精确时间戳。为简化监管审查，我们把这些产物直接映射到标准合规框架，满足 SOC 2（CC7.3、CC7.4）、ISO 27001（A.16.1.5、A.12.4.1）与 NIST 800-53（IR-4、AU-2、AU-12）中的具体强制要求。在我们的预部署评测期间，风险官们反复强调，这份不可更改的账本是系统最关键的一项资产。

### VII-E 人类审批边界

Sentinel-RL 通过一套严格执行的分层权限架构来管理运营风险（图 5）。常规情报收集——例如查询 EDR 平台或拉取日志——属于 **Tier 1**。这些动作完全自主执行，只是为可见性而记录。**Tier 2** 涵盖可逆的遏制战术，如隔离一个收件箱。这些会自动执行，但只有在内部评论者智能体验证了底层逻辑之后。**Tier 3** 涵盖高风险、不可逆的操作，如断开一台主机或关闭一个网段。这些命令被完全硬闸门挡下，除非人工分析师在仪表盘上手动点击批准按钮，否则无法继续。倘若环境变得不稳定，管理员可以触发一个全局 kill switch，在一分钟内把整个架构降级回基本的、基于规则的日志记录，而无需重启管线。

## VIII 相关工作

### VIII-A LANL 上的横向移动检测

自其发布以来，LANL 数据集 [1] 一直是追踪横向移动的公认试验场。早期的突破把这种追踪当作一个结构化的图问题，Bowman 等人 [4] 以及极具影响力的 Euler 框架 [5] 为链路预测技术建立了最初的基线。其后 PIKACHU [6] 与 LMDetect [7] 等架构把这些边界大幅向前推进，利用复杂的子图分类把真阳性率与整体 F1 分数推入 90 分位的高段。更近期，社区开始转向在多样、异构网络上预训练的图基础模型 [20][21]，在平均精确率上取得了巨大飞跃。

虽然 Sentinel-RL 面对这些最先进的检测器时完全站得住脚（表 III），但追逐零头小数点的准确率提升并非我们的主要目标。相反，我们的核心贡献在于弥合被动检测与自动化遏制之间的鸿沟。我们把一个能力很强的分类器包裹进一个经加固、企业就绪的响应架构中，把焦点从单纯识别威胁转向安全地中和它。

### VIII-B 面向自主网络防御的 RL

为主动网络防御设计强化学习智能体，需要穿行于极其复杂、高风险的环境。我们把 Sentinel-RL 建立在 Foley 等人 [8] 最近形式化的一组核心原则之上。我们直接把他们的发现整合进我们的引擎：具体而言，智能体使用**稀疏的、目标驱动的奖励**学习，其效果远好于稠密、重度工程化的信号；并且除非系统原生地把环境感知为图，否则稳健的跨网络泛化是不可能的。

我们把这套逻辑与 Hicks 等人 [9] 的洞见配对，他们关于阶段感知可解释性的研究直接启发了我们编排层内的叙述转化机制。虽然这一领域的大量基础研究重度依赖像 CybORG [10] 与 CybORG++ [11] 这样的专门仿真沙箱，我们的工作聚焦于真实环境的执行。展望未来，我们的模块化架构处于有利位置，可以吸纳新兴的加速技术——例如用 LLM 为 RL 智能体提供早期教师信号 [22]——这些技术近来已展示出大幅缩短训练时间的能力。

### VIII-C 智能体化 SOC 架构

把语言模型直接整合进安全运营的商业举措，其速度已远超正式的、经同行评审的验证。我们指出微软 Security Copilot [23] 等平台以及近期全面的威胁综述 [24] 是这种「行业先行」势头的典型例子。然而，部署未受检查的自动化，往往会忽视安全中心的实际现实。为确保我们的架构保持运营可行性，我们把人在环路的设计锚定在 Vermeer 等人 [19] 的实证观察上。他们对分析师在压力下实际如何分诊告警的详细描述，对 Sentinel-RL 构成了一条硬约束，精确规定了我们可以合理地期望一名人类操作员处理什么。

### VIII-D 方法论基础

最后，我们刻意设计评测框架，以避免那些经常削弱网络安全领域应用机器学习研究的系统性陷阱。我们严格遵循 Arp 等人 [25] 建立的架构护栏，明确剥离了那些常常虚增已报告性能的空间与时间偏差、纯实验室式的无菌测试，以及不切实际的威胁假设。与这些约束配对，我们完全拥抱了 Bilot 等人 [26] 所倡导的、在基于图的检测中绝对、透明可复现性的标准。

## IX 结论

借助 Sentinel-RL，我们展示了一种通往智能体化 SOC 的根本不同路径。通过主动把拓扑推理这一复杂的空间负担从语言模型卸载到一个专门的图编码器与一个 PPO 驱动的策略上，我们构建出一个真正可扩展的神经—符号架构。

我们在 LANL 基准上的端到端评测证明了这种可行性。系统在短短 14.2 分钟内成功摄入了 2400 万边的巨型子图，并在第 99 百分位、不到 2.45 秒内可靠触发其告警管线。此外，强化学习策略在 200 次迭代内收敛到 8.74 的平均回合回报，最终在完全未见的数据上交付 0.91 的精确率与 0.87 的召回率。关键在于，整个运营生命周期——从最初的异常事件到最终、完整综合的遏制建议——在中位仅 6.3 秒内解析完毕。

然而，这些原始指标只是故事的一部分。我们相信，这项工作最持久的贡献，在于构建它所必需的那些实际工程解决方案。用两阶段 CREATE 策略绕开热节点锁竞争、通过 HPC 锚节点模式中和集群延迟，以及设计 §VII 详述的稳健企业控制面，都是高度可复用的模式。它们共同把 Sentinel-RL 从一个脆弱的研究原型，提升为一个可信的、经加固的、可随时用于机构部署的框架。

## 可复现性

我们严格致力于透明、可验证的研究。§VI 中详述的所有数值结果，都可以使用所提供的 Cypher 预物化查询（Listing 1）、指定的 AlertEngine 阈值、我们确切的 PPO 超参映射（表 I），以及文档化的 SLURM 锚节点分配策略来完全复现。
