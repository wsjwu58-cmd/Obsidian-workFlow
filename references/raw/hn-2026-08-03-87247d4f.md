# Prevent cognitive debt by manually retyping LLM-generated code

> 原文链接：https://ankursethi.com/blog/prevent-cognitive-debt-by-manually-retyping-llm-generated-code/
> 全文抓取：2026-08-04（已翻译）

尽管[我在四月份所说的话] (https://ankursetihi.
com/blog/coding-coiders-aidents-person-projects/,我仍在使用个人项目的编码助理。
使用它们来一张照片 整个功能让我感到不满意和迷惑, 但我确实喜欢利用它们 快速前进 通过我项目的无聊部分。
然而,允许我的编码助理在我的项目中自由漫游, 留给我大量的认知债务。
我可能讨厌翻过Django的文件 来想出如何在我的网站上添加标签, 但我仍想从根本上了解它是如何运作的。
仅仅因为一个问题是无聊的 并不意味着我想完全放弃 我对机器解决方案的理解
当然,我可以检查一下LLM的每行代码
在2026年这个被诅咒的年份, 大部分开发商都希望这样做。
机器人提高公关公关, 人类审查它们。
这是一个勇敢的新世界。
但我不喜欢审查人工智能生成的公关
数以百计的线条 过于防守 刻薄 粗俗错误的代码 一点都不好玩
我可能会不情愿为雇主做这件事情, 同时确保雇主尽快成为前雇主, 但我绝对不会为个人项目做这件事。
个人项目必须比其他所有项目更有趣。
个人项目工作的欢乐来自[进程,而不是结果](https://ankursetihi)。

那么男孩该做什么呢?
我要怎么把无聊的工作 卸下给LLMS 而不放弃对我自己工作的控制 和对垃圾机器的认知?
我提出了一个非常低效,也许有点滑稽的解决方案:我请我的编码助理在聊天中生成代码,然后手工完成所有编辑。
我的个人项目中所有探员档案里都有这些指示
」我想了解这个项目的每一行代码。
永远不要创建、编辑、移动、重命名或删除工程文件,除非我明确要求你这样做。
相反,让我看看聊天中的每一个编辑提议, 这样我就可以用手动键入。
> >
> 不运行修改工程文件、安装依赖关系或更改存储库状态的命令, 除非我明确要求该动作 。
相反,告诉我那些命令 在聊天 这样我就可以手动运行它们。
> >
我是一个经验丰富的开发者。
除非明确要求,否则不得解释语法、API、编程概念或实施细节。
使用LLMs让我比不使用LMs更快工作, 但我比那些愿意让机器为他们思考的人要慢。
而不是更快10x, 我可能只有2x更快。
但我在速度上失去的, 在更深入地理解我的代码方面,我得到的。
当我手动把LLM的每行代码都输入到我的编辑里时, 我建立了一个心理模型, 来说明它是如何运作的, 并且适合我现有的代码库。
如果我不理解API或算法, 我可以停下来查查, 或者请LLM解释一下。
键入密码迫使我减速 这意味着我更可能发现幻觉 或者LLM可能做出的错误的设计选择
我可以清理代码 当我去,重组它, 重新构思它, 补充评论, 和一般调整它 适合我自己的口味。
最重要的是,这个工作流程允许我在我的代码库中 绘制一个空间地图。
我知道代码库里每个功能 都住在哪里
当我需要改变的时候,我知道我在哪里需要改变。
它不仅帮助我在项目中更快地工作,而且使我今后更容易更迅速地指导法学硕士。
当我学会了青少年的代码, 有经验的程序员会经常告诉我 永远不要复制和粘贴代码 在我的项目中。
如果我从一本书中学习,我被建议把所有的例子都复制到我的电脑里,确保我能运行它们。
如果我从博客文章或论坛的答案中学习,
手动将生成的 LLM 输入到我的代码库, 感觉就像完全相同的学习过程。
这也许不是最有效的与LLM合作的方式,但我重视对生产力的理解。
我已经做了几个月了 对我一直很有效
我计划继续使用这个工作流程 尽可能长的时间。
我担心软件行业 正在承担大量的认知债务 我们必须尽快还清
将来有一天,我们再也无法理解我们数字基础设施的很大一部分是如何组合在一起的。
我个人可能无法改变整个行业的走向, 但我至少可以确保我完全理解我把软件放入世界的软件。
任何其他的都是专业渎职行为。
