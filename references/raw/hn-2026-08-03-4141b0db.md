# Bonsai

Bonsai 是一个用于在 OCaml 中构建高性能、响应式 Web 应用的 UI 库，部分灵感来源于 [Elm](https://elm-lang.org/)。它被用于构建 Jane Street 内部几乎所有的 Web 应用，从公司目录到监控和交互交易系统的工具，无所不包。一个带有少量交互性的简单 Bonsai 组件如下所示：

```ocaml
module Dice = struct
  let faces =
    [ "⚀"; "⚁"; "⚂"; "⚃"; "⚄"; "⚅" ]
  ;;

  let component (graph @ local) =
    (* 组件被实现为纯函数式状态机。 *)
    let face, set_face = Bonsai.state (List.hd_exn faces) graph in
    (* 组件是增量渲染的，仅在状态的相关部分发生变化时才会重新渲染。 *)
    let%arr face and set_face in
    {%html|
      <div>
        You rolled a #{face}
        <button
          style="" on_click=%{fun _ ->
            let index = Random.int (List.length faces) in
            set_face (List.nth_exn faces index)}
        >
          Roll the dice
        </button>
      </div>
    |}
  ;;
end
```

组件被实现为纯函数式状态机，并且易于组合。框架内部的增量机制意味着值不会在必要之前被重新计算。这适用于每一个值，而不仅仅是视图。

## 为什么选择 Bonsai？

其他 Web 框架倾向于将状态、增量性和渲染合并到一个单一的抽象中，即 UI 组件。相比之下，Bonsai 允许你按需组合状态和增量性原语。那些用于防止用户交互期间整个页面重新渲染的原语，同样可以用于对实时更新的数据集上的昂贵业务逻辑计算进行增量优化。（如果你熟悉 React，可以想象所有东西都使用了非常类似于 hooks 的机制，并且状态在组件层级之外进行管理。）

由于状态不与显式组件关联，因此有一个广泛的 API 用于管理用户与页面交互时状态的生命周期和作用域。例如，如果你想在另一个 UI 组件中嵌入一组有状态的 UI 组件（比如在选项卡界面中），Bonsai 会为你处理状态管理，而无需你手动将每个内部组件的状态提升到应用的顶层模型。关于状态如何组合的更多示例，请参阅 Bonsai 创建者撰写的这篇[组合对比](https://tyoverby.com/composition-comparison/)。

而且，由于 Bonsai 是用 OCaml 编写的，因此可以在后端和前端使用相同的语言和类型。很难夸大这对可读性以及保持大型 Web 应用代码库可管理性的影响，尤其是当你广泛使用 OCaml 的类型系统来减少错误时。在 Jane Street，许多内部系统以前只有终端 UI，而该框架使得将现有类型和业务逻辑移植到 Web 变得容易。

Bonsai 还附带了一个强大的模板语言、对组件特定样式表的支持，以及一个用于整个应用自动化测试的系统。

## 富有表现力的测试，让你免于手动点击应用

Bonsai 最强大的功能之一是它能够让你轻松编写逼真的测试，在测试中你可以以编程方式操作 UI 元素并观察 DOM 的演变。

在以下示例中，我们正在测试一个用户选择器的行为。你在文本框中输入的任何内容都会被附加到一条简短的“hello”消息中：

```ocaml
let%expect_test "shows hello to a specified user" =
  let handle = Handle.create (Result_spec.vdom Fn.id) hello_textbox in
  Handle.show handle;
  [%expect
    {|
    <div>
      <input oninput> </input>
      <span> hello  </span>
    </div> |}];
  Handle.input_text handle ~get_vdom:Fn.id ~selector:"input" ~text:"Bob";
  Handle.show_diff handle;

[%expect
    {|
      <div>
        <input oninput> </input>
-      <span> hello  </span>
+      <span> hello Bob </span>
      </div> |}];
```

请注意，这里有两个 [expect
块](https://blog.janestreet.com/the-joy-of-expect-tests/)。（这允许你在给定场景中做出多个断言，并将设置/辅助代码限定在该场景内。）

第一个使我们的 UI 可见，第二个——包含一个差异——展示了在你以编程方式输入一些文本后的某些行为。Bonsai 甚至会向你展示 HTML 属性或类名如何响应用户输入而变化。测试可以包含模拟服务器调用，并且可以涉及不仅限于 UI 的变化，还包括驱动它的状态的变化。有了这样的测试，你可以在不打开浏览器的情况下编写整个组件。

## Bonsai 实际上是一个库的集合

呃，有一个小问题：Bonsai 本身——这个库——实际上比上述描述听起来更通用。它允许你构建通用的增量式、可组合状态机。[Bonsai_web](https://github.com/janestreet/bonsai_web) 构建在该核心库之上，专门用于交互式基于浏览器的 UI，但我们也有 [Bonsai_term](https://github.com/janestreet/bonsai_term) 用于构建交互式 *终端* 基础的 UI。甚至还有一个愚人节原型 Bonsai\_vr 用于响应式虚拟现实 UI。

完整的 Bonsai 库套件：

### 通用库

[Bonsai](https://github.com/janestreet/bonsai) 是一个用于构建增量式、可组合状态机的库。

* [测试](https://github.com/janestreet/bonsai_test)

### 基于浏览器的 UI 库

[Bonsai_web](https://github.com/janestreet/bonsai_web) 是一个使用 `bonsai` 构建交互式基于浏览器的 UI 的库。

* [示例](https://github.com/janestreet/bonsai_examples)
* [组件](https://github.com/janestreet/bonsai_web_components)
* [测试](https://github.com/janestreet/bonsai_web_test)
* [基准测试](https://github.com/janestreet/bonsai_bench)
  
### 基于终端的 UI 库

[Bonsai_term](https://github.com/janestreet/bonsai_term) 是一个使用 `bonsai` 构建交互式基于终端的 UI 的库。

* [示例](https://github.com/janestreet/bonsai_term_examples)
* [组件](https://github.com/janestreet/bonsai_term_components)
* [测试](https://github.com/janestreet/bonsai_term_test)

### 预处理器

Bonsai 网页应用通常使用以下预处理器：

- [ppx_html](https://github.com/janestreet/ppx_html) 是一个用于编写 HTML 的预处理器，类似于 [JSX](https://en.wikipedia.org/wiki/JavaScript_XML)。
- [ppx_css](https://github.com/janestreet/ppx_css) 是一个用于编写 CSS 的预处理器。
