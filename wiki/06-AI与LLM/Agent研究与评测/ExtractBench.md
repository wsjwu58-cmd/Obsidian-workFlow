# ExtractBench

给"照着模式从文档里抽数据"定一把尺子：不仅看抽得准不准，还看抽得全不全、有没有出处、花了多少钱。

## 检索问题（Q&A）
- 智能体做结构化信息提取怎么评估？→ 本条目：ExtractBench 四维指标（准确性 / 完整性 / 溯源 / 成本）
- 长文档提取为什么容易漏？→ 视觉模型截断记录列表；编码智能体准确但贵

## 结构化提炼

### 核心论点
企业智能体的模式引导提取（schema-guided extraction）需要同时度量值准确性、记录完整性、证据溯源与实际成本；ExtractBench 是首个四维同测的基准。

### 逻辑骨架
- 问题：企业工作流用 Agent 提取文档，但缺少"完整 + 溯源 + 成本"的综合评测
- 方案：370 份企业文档、4869 页、8 个业务领域、67 种文档类型；可扩展模式 + 三重数据校验（独立系统一致性 / 合成已知值 / 人工核验）
- 指标：顺序不敏感值 F1 + 词级/页面级溯源 F1 + 实际成本
- 结论：LlamaExtract Agentic Plus 全面第一——准确性与编码智能体相当，成本仅为小部分

### 关键概念（费曼式）
- 模式引导提取：像填表格，模式就是表头，Agent 负责把文档内容填到正确格子里
- 溯源 F1：抽出的每条数据都能指出"出自文档哪一页哪句话"，防止瞎编

## 深度追问

### 苏格拉底式质疑
1. "成本仅为小部分"是否计入了幻觉纠错的隐性成本？
2. 370 份文档的领域分布是否偏向英语/西式文档？中文企业文档表现未知
3. 溯源指标衡量的是"有出处"，还是"出处真的支持该结论"？

### 背景与盲区
- 背景：视觉语言模型擅长版面理解，但长上下文会"记不住尾部记录"；编码智能体靠工具循环弥补
- 盲区：表格嵌套、扫描件 OCR 错误、多语言文档未覆盖

### 溯源与验证
- 数据集与评测代码公开（HuggingFace / GitHub），可复现

## 联想与缝合

### 跨学科类比
像"审计抽查"：光看总账（准确率）不够，还要抽凭证（溯源）看每笔数字有没有单据支撑。

### 与知识库联系
- 与 [[MarkItDown]]：前者"把文档转成 Markdown 供 LLM 读"，后者"从文档抽结构化字段"，同属 RAG/文档处理链路
- 与 [[RAG处理优化]]：提取质量直接决定 RAG 知识库的入库数据质量

### 底层模型
- 质量四维框架：准确性 / 完整性 / 可追溯性 / 成本——可迁移到任何"AI 干活"的验收标准

## 场景化转译

### 行动清单
- [ ] 做文档类 Agent 时，验收指标加上"溯源 F1"，防止模型幻觉式填充
- [ ] 长文档任务优先编码智能体或分块策略，规避视觉模型截断

### 避坑指南
- 别只看准确率：漏抽（完整性低）比抽错更隐蔽，长文档场景尤其严重
- 视觉模型 + 超长文档 = 高风险组合

## 可视化

| 维度 | 指标 | 关注点 |
|------|------|--------|
| 值准确性 | 顺序不敏感 F1 | 抽得对不对 |
| 完整性 | 记录覆盖 | 抽得全不全 |
| 溯源 | 词级/页面级 F1 | 有没有出处 |
| 成本 | 实际调用 | 值不值 |
