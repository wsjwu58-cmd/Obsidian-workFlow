# 4-编程语言与状态枚举
本文档介绍 Judge0 中两个核心枚举类型：**编程语言（Language）** 和 **执行状态（Status）**。这两个枚举是代码执行平台的基础数据模型，分别定义了系统支持的编程语言种类以及代码提交的执行结果状态。

## 状态枚举（Status）

### 状态定义

Status 枚举类位于 `app/enumerations/status.rb`，定义了代码提交的 14 种执行状态。每种状态都有唯一的数字标识 ID 和友好的英文描述名称。

### 运行时错误状态映射

Status 枚举包含一个特殊的类方法 `find_runtime_error_by_status_code`，用于将 Linux 系统信号码映射为对应的运行时错误状态。这是处理程序异常退出的核心逻辑。

```ruby
def self.find_runtime_error_by_status_code(status_code)
  case status_code.to_i
    when 11 then Status.sigsegv    # SIGSEGV - 段错误
    when 25 then Status.sigxfsz    # SIGXFSZ - 文件大小超限
    when 8  then Status.sigfpe     # SIGFPE  - 浮点异常
    when 6  then Status.sigabrt   # SIGABRT - 程序中止
    else Status.other             # 其他错误
  end
end
```

该方法在 `IsolateJob` 的 `determine_status` 方法中被调用，当隔离环境返回 "SG"（Signaled）状态时，根据退出信号确定具体的运行时错误类型。

## 编程语言配置（Language）

### 语言模型结构

Language 模型定义在 `app/models/language.rb`，对应数据库中的 `languages` 表。

```ruby
class Language < ApplicationRecord
  validates :name, presence: true
  validates :source_file, :run_cmd, presence: true, unless: -> { is_project }
  default_scope { where(is_archived: false).order(name: :asc) }
  
  def is_project
    name == "Multi-file program"
  end
end
```

数据库表结构包含以下字段：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `id` | integer | 语言唯一标识符 |
| `name` | string | 语言显示名称（如 "Python (3.8.1)"） |
| `source_file` | string | 源代码文件名（如 "main.py"） |
| `run_cmd` | string | 运行命令的模板字符串 |
| `compile_cmd` | string | 编译命令的模板字符串（可选） |
| `is_archived` | boolean | 是否已归档（默认 false） |

### 语言配置文件

Judge0 将语言配置分为两个文件：`db/languages/active.rb`（当前活跃语言）和 `db/languages/archived.rb`（已归档语言）。

**活跃语言配置示例：**

### 命令模板语法

语言配置中的 `run_cmd` 和 `compile_cmd` 使用 `%s` 作为源代码文件的占位符。当执行时，系统会将 `%s` 替换为实际的安全参数。

**模板使用示例：**

```ruby
# Python 解释型语言 - 只需运行命令
run_cmd: "/usr/local/python-3.8.1/bin/python3 script.py"

# C 编译型语言 - 编译 + 运行
compile_cmd: "/usr/local/gcc-9.2.0/bin/gcc %s main.c"
run_cmd: "./a.out"

# C++ 编译型语言 - 需要设置库路径
compile_cmd: "/usr/local/gcc-9.2.0/bin/g++ %s main.cpp"
run_cmd: "LD_LIBRARY_PATH=/usr/local/gcc-9.2.0/lib64 ./a.out"
```

Sources: [active.rb](#root/GfohWlPypc6W) Sources: [active.rb](#root/eEREKFHouDDP)

### 特殊语言：多文件项目

ID 为 89 的 "Multi-file program" 是一种特殊语言，允许用户上传 ZIP 压缩包，包含多个源文件和自定义的 `compile.sh`/`run.sh` 脚本。

```ruby
{
  id: 89,
  name: "Multi-file program",
  is_archived: false
  # 注意：没有 source_file、run_cmd、compile_cmd
  # 用户需要提供 compile.sh 和/或 run.sh 脚本
}
```

对于这种特殊语言，`is_project` 方法返回 `true`，跳过源代码文件的验证。

## API 中的枚举表示

Status 和 Language 都配有专门的序列化器，用于生成 API 响应：

## 状态与语言的关联使用

### Submission 模型中的关联

在 Submission 模型中，通过 `enumeration :status` 声明建立了与 Status 枚举的关联：

```ruby
class Submission < ApplicationRecord
  # ...验证规则...
  enumeration :status
  
  def status
    Status.find_by(id: status_id)
  end
  
  def status=(status)
    self.status_id = status.id
  end
end
```

Sources: [submission.rb](#root/zNtvFS5fpULO) Sources: [submission.rb](#root/7pfV2t0bJRnD)

### 控制器中的状态检查

在 SubmissionsController 的 `destroy` 方法中，通过 Status 枚举检查提交是否可以删除：

```ruby
def destroy
  submission = Submission.find_by!(token: params[:token])
  if submission.status == Status.queue || submission.status == Status.process
    render json: {
      error: "submission cannot be deleted because its status is #{submission.status.id}"
    }, status: :bad_request
    return
  end
  submission.delete
end
```

Sources: [submissions\_controller.rb](#root/HrtOc2LBsGzB)

### IsolateJob 中的状态更新

IsolateJob 是实际执行代码的核心组件，它根据执行结果设置不同的 Status：

```ruby
# 开始处理时
submission.update(status: Status.process, started_at: DateTime.now)

# 编译失败时
submission.status = Status.ce

# 运行验证时
submission.status = determine_status(metadata[:status], submission.exit_signal)
```
