

## 业务关系

- **类别(Category)** 是基础分类，分为菜品分类和套餐分类两种类型
- **菜品(Dish)** 属于某个菜品分类，可以有多种口味(DishFlavor)
- **套餐(Setmeal)** 属于某个套餐分类，可以包含多个菜品(SetmealDish关联)

关系图：
```
类别(Category)
├── 菜品分类
│   └── 菜品(Dish)
│       └── 菜品口味(DishFlavor)
└── 套餐分类
    └── 套餐(Setmeal)
        └── 套餐菜品关系(SetmealDish)
```

**启用/停用**
- 直接修改菜品状态
- 如果停用菜品，且该菜品被套餐关联，则同时停用相关套餐

### 套餐(Setmeal)管理

**新增**
- 无特殊限制，创建套餐及关联菜品信息

**删除**
- 套餐必须处于停售状态，否则抛出 [DeletionNotAllowedException](file://D:\download\sky-take-out-master\sky-take-out-master\source\day01\houduan\sky-take-out\sky-common\src\main\java\com\sky\exception\DeletionNotAllowedException.java#L2-L8)

**修改**
- 无特殊限制，可修改套餐信息和关联菜品

**启用/停用**
- 启用套餐时，如果套餐内包含停售的菜品，则不能启用，抛出 [DeletionNotAllowedException](file://D:\download\sky-take-out-master\sky-take-out-master\source\day01\houduan\sky-take-out\sky-common\src\main\java\com\sky\exception\DeletionNotAllowedException.java#L2-L8)

@Test
    public void test() throws IOException {
        //创建HttpClient对象
        CloseableHttpClient client= HttpClients.createDefault();
        //创建请求对象
        HttpGet httpGet=new HttpGet("http://localhost:8080/user/shop/status");
        //发送请求，接收响应结果
        CloseableHttpResponse response=client.execute(httpGet);

        //解析响应结果
        int statusCode=response.getStatusLine().getStatusCode();
        System.out.println(statusCode);

        HttpEntity entity=response.getEntity();
        String data= EntityUtils.toString(entity);
        System.out.println("返回数据："+data);

        //释放资源
        response.close();
        client.close();
    }

| @EnableCaching | 开启缓存注解功能，通常加在启动类上                           |

在spring boot项目中，使用缓存技术只需在项目中导入相关缓存技术的依赖包，并在启动类上使用@EnableCaching开启缓存支持即可。

## 订单管理

### 1. **orders（订单表）**

- **主表**，记录订单的基本信息。
- **字段示例**：`id`, `user_id`, `status`, `pay_status`, `amount`, `address`, `phone`, `consignee`, `order_time`, `checkout_time`, `cancel_time` 等。
- **业务关系**：
  - 一个订单属于一个用户。
  - 一个订单包含多个订单明细。
  - 一个订单可以有支付、状态变更等操作记录。

### 2. **order_detail（订单明细表）**

- **从表**，记录订单中的具体商品信息。
- **字段示例**：`id`, `order_id`, `dish_id`, `setmeal_id`, `name`, `price`, `number` 等。
- **业务关系**：
  - 一个订单对应多个订单明细。
  - 一个订单明细关联一个菜品或套餐。

### 3. **address_book（地址簿表）**

- **用户地址表**，记录用户的收货地址。
- **字段示例**：`id`, `user_id`, `consignee`, `phone`, `detail`, `city_name`, `district_name` 等。
- **业务关系**：
  - 一个用户可以有多个地址。
  - 一个订单关联一个地址。

### 4. **shopping_cart（购物车表）**

- **用户购物车表**，记录用户加入购物车的商品。
- **字段示例**：`id`, `user_id`, `dish_id`, `setmeal_id`, `name`, `price`, `number`, `create_time` 等。
- **业务关系**：
  - 一个用户对应一个购物车（逻辑上）。
  - 购物车中的商品在提交订单后会清空。

### 5. **user（用户表）**

- **用户表**，记录用户信息。
- **字段示例**：`id`, `openid`, `name`, `phone`, `status`, `create_time` 等。
- **业务关系**：
  - 一个用户可以下多个订单。
  - 一个用户可以有多个地址。

###  **业务操作流程**

#### 用户端：

1. **查看购物车** → `shopping_cart`
2. **选择地址** → `address_book`
3. **提交订单** → 创建 `orders` 记录，写入 `order_detail`，清空 `shopping_cart`
4. **支付订单** → 更新 `orders` 中的支付状态
5. **查看历史订单** → 关联查询 `orders` + `order_detail`
6. **取消/再来一单** → 更新 `orders` 状态或复制到购物车

#### 管理端：

1. **订单搜索/统计** → 查询 `orders` 并统计状态
2. **接单/拒单/派送/完成** → 更新 `orders` 状态
3. **查看订单详情** → 关联查询 `orders` + `order_detail`

### cron表达式

**cron表达式**其实就是一个字符串，通过cron表达式可以**定义任务触发的时间**

**构成规则：**分为6或7个域，由空格分隔开，每个域代表一个含义

每个域的含义分别为：秒、分钟、小时、日、月、周、年(可选)

cron表达式在线生成器：https://cron.qqe2.com/

**通配符：**

\* 表示所有值； 

? 表示未说明的值，即不关心它为何值； 

\- 表示一个指定的范围； 

, 表示附加一个可能值； 

/ 符号前表示开始时间，符号后表示每次递增的值；

**cron表达式案例：**

*/5 * * * * ? 每隔5秒执行一次

0 */1 * * * ? 每隔1分钟执行一次

0 0 5-15 * * ? 每天5-15点整点触发

0 0/3 * * * ? 每三分钟触发一次

0 0-5 14 * * ? 在每天下午2点到下午2:05期间的每1分钟触发 

0 0/5 14 * * ? 在每天下午2点到下午2:55期间的每5分钟触发

0 0/5 14,18 * * ? 在每天下午2点到2:55期间和下午6点到6:55期间的每5分钟触发

0 0/30 9-17 * * ? 朝九晚五工作时间内每半小时

0 0 10,14,16 * * ? 每天上午10点，下午2点，4点

## WebSocket

WebSocket 是基于 TCP 的一种新的**网络协议**。它实现了浏览器与服务器全双工通信——浏览器和服务器只需要完成一次握手，两者之间就可以创建**持久性**的连接， 并进行**双向**数据传输。

**HTTP协议和WebSocket协议对比：**

- HTTP是**短连接**
- WebSocket是**长连接**
- HTTP通信是**单向**的，基于请求响应模式
- WebSocket支持**双向**通信
- HTTP和WebSocket底层都是TCP连接

**WebSocket缺点：**

服务器长期维护长连接需要一定的成本
各个浏览器支持程度不一
WebSocket 是长连接，受网络限制比较大，需要处理好重连

**结论：**WebSocket并不能完全取代HTTP，它只适合在特定的场景下使用

服务端组件

@Component
@ServerEndpoint("/ws/{sid}")
public class WebSocketServer {

    //存放会话对象
    private static Map<String, Session> sessionMap = new HashMap();
    
    /**
     * 连接建立成功调用的方法
     */
    @OnOpen
    public void onOpen(Session session, @PathParam("sid") String sid) {
        System.out.println("客户端：" + sid + "建立连接");
        sessionMap.put(sid, session);
    }
    
    /**
     * 收到客户端消息后调用的方法
     *
     * @param message 客户端发送过来的消息
     */
    @OnMessage
    public void onMessage(String message, @PathParam("sid") String sid) {
        System.out.println("收到来自客户端：" + sid + "的信息:" + message);
    }
    
    /**
     * 连接关闭调用的方法
     *
     * @param sid
     */
    @OnClose
    public void onClose(@PathParam("sid") String sid) {
        System.out.println("连接断开:" + sid);
        sessionMap.remove(sid);
    }
    
    /**
     * 群发
     *
     * @param message
     */
    public void sendToAllClient(String message) {
        Collection<Session> sessions = sessionMap.values();
        for (Session session : sessions) {
            try {
                //服务器向客户端发送消息
                session.getBasicRemote().sendText(message);
            } catch (Exception e) {
                e.printStackTrace();
            }
        }
    }
