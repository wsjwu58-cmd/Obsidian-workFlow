# DungeonBench

把 LLM 放进龙与地下城的战场：规则密密麻麻、资源要精打细算，测的是"规则密集型战术推理"而不是聊天能力。

## 检索问题（Q&A）
- LLM 做长期规划 / 资源管理的能力怎么测？→ 本条目：DungeonBench 双轨道设计（遭遇战 + 一日冒险）
- 为什么 LLM 单场能赢、连续作战就崩？→ 资源预算、休息时机、规则纪律

## 结构化提炼

### 核心论点
游戏是天然的决策评测场；DungeonBench 用 D&D 战斗覆盖"几何、时机、资源、规则交互"同时作用的战术推理，并保留模拟器常抽象掉的机制。

### 逻辑骨架
- 问题：现有游戏基准对规则密集型战术推理测试不足
- 方案：基于 2014 SRD 的模拟器，每步给出完整战术观察 + 可执行选项索引（移动 / 攻击 / 法术 / 反应 / 准备 / 稀缺资源）
- 双轨道：遭遇战（单场局部发挥）→ 一日冒险（生命值 / 法术位 / 消耗品 / 短休串联，逼你权衡眼前与长期）
- 结论：前沿模型赢得直接遭遇战，但串联后暴露资源预算与休息时机失败

### 关键概念（费曼式）
- 行动经济性：每回合能做的动作有限，怎么分配"次数"本身就是策略
- 掩蔽动作强化学习：让 RL 代理只在合法动作里选，避免无效输出

## 深度追问

### 苏格拉底式质疑
1. D&D 规则复杂度能否代表真实世界的战术复杂度？迁移性存疑
2. "完整观察"包含全部状态，是否反而掩盖了真实场景的"信息不完备"难点？
3. 失败归因是策略问题还是规则理解问题？评测能否区分？

### 背景与盲区
- 背景：游戏基准的价值——把决策变成可衡量的结果；此前游戏套件多偏"操作"而非"规则推理"
- 盲区：多智能体对抗（PVP）、欺骗与信息隐藏未覆盖

### 溯源与验证
- 决策流与模拟器共享，支持启发式控制器、LLM 策略、学习型排序器、掩蔽 RL 代理对比

## 联想与缝合

### 跨学科类比
像"围棋 vs 军棋"：前者是完美信息下的计算，后者叠加资源管理与规则博弈——LLM 目前更像会下围棋但不会管后勤的参谋。

### 与知识库联系
- 与 [[在线策略交互与模仿学习]]：一个测交互中的策略，一个训交互中的策略，形成"训-测"闭环
- 与 [[Agent搭建]]：评测的是 ReAct 式"观察→决策"循环在长程任务上的表现

### 底层模型
- 局部最优 vs 全局生存的权衡（贪心策略失效场景）
- 约束满足下的决策（行动经济性 = 约束优化）

## 场景化转译

### 行动清单
- [ ] 设计 Agent 评测时加入"串联任务"——单任务过关不代表长程可靠
- [ ] 检查自己的 Agent 是否对"资源预算"有显式管理（token、额度、时间）

### 避坑指南
- 别用"赢得单场战斗"证明 Agent 强——连续场景才是照妖镜
- 规则密集型任务先给 Agent 限定"合法动作集合"，否则会在无效输出上浪费推理

## 可视化
