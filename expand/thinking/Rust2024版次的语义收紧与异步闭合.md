# Rust 2024 版次的语义收紧与异步闭合

> 论点：采集器给这条素材打的标签是「Move 语义 / Borrow Checker 演进」，对照官方博文原文，这个概括**失焦了**——1.85.0 并没有直接的 Move 语义变更。真正的三条主线是：① Rust 2024 Edition 集中落地一批「语义收紧」（临时作用域 / drop 顺序、match 擦除保留、RPIT 生命周期捕获规则、unsafe 边界收缩）；② async closures（AsyncFn 家族）补齐异步借用缺口；③ 版本号不承载语义里程碑，语义演进靠 edition 机制约三年一拍。其中「unsafe 边界从 lint 升级为语言规则」是理解这次版次的关键。

## 一、官方博文说了什么（压缩）

Rust 1.85.0（2025-02-20，The Rust Release Team）同时稳定了 2024 Edition，官方口径为「史上最大版次」。主要变更：语言层（RPIT 生命周期捕获规则、if let / 尾表达式临时作用域、match 擦除保留、unsafe extern 块与 unsafe 属性、static mut 引用默认 deny、never 类型回退、gen 关键字预留）、标准库（prelude 增 Future / IntoFuture、Box<[T]> 可迭代、set_var / remove_var 转 unsafe）、Cargo（rust-version 感知解析器）、Rustfmt（style editions）、async closures 稳定、`#[diagnostic::do_not_recommend]`、元组 FromIterator / Extend 扩展到 1–12 元、一批 API 与 const 上下文稳定。

## 二、纠偏：这次版次没有「Move 语义变更」

- 1.85 的 release notes 里没有直接的 Move 语义变更。与「Move」沾边的只有两处间接信号：
  - **match ergonomics 保留**：禁用部分模式组合，影响默认绑定模式（ref / ref mut / move）的解析——属于「约束现在、打开未来」，为后续改进腾空间。
  - **真正的借用/生命周期变更在类型系统侧**：RPIT 生命周期捕获规则（`impl Trait` 默认捕获作用域内全部生命周期参数，可用 `use<..>` 精确捕获），这是签名层面的语义演进，不是 Move 语义。
- 结论：归档为「Move 语义 / Borrow Checker 演进」会误导检索。正确的归档视角是「版次语义演进 + unsafe 显式化 + 异步借用补课」。

## 三、独立分析 1：edition 是「语义债务银行」，约三年一清偿

对照几种语言的兼容策略：

| 语言 | 机制 | 特点 |
|------|------|------|
| Rust | edition（2015 / 2018 / 2021 / 2024） | per-crate 选择语义，新旧版次可互操作；`cargo fix` 保守自动迁移 |
| Python | `__future__` 导入 | 按文件粒度逐特性开启，无自动迁移工具 |
| Go | 工具链整体升级 | 无 per-package 语义分叉，靠工具链统一演进 |
| C++ | 标准版本宏（`__cplusplus`） | 语义分叉由宏与 ABI 碎片承担，无迁移工具 |

Rust 的独特点：语义变更被「迁移窗口」封装——编译器同时理解两套语义，crate 之间通过版次互操作层对接，迁移由每个 crate 自己决定何时切换。代价是编译器复杂度与版本矩阵测试成本；收益是生态不出现「Python 2/3」式断代。2024 版次是多年积累的一次性清偿：临时作用域、drop 顺序这类**运行时语义变更**，只有放进版次才可能不破坏存量代码。

## 四、独立分析 2：主线是「unsafe 收缩」，不是「安全能力扩张」

2024 版次的语言变更里，过半与 unsafe 边界有关：unsafe extern blocks、unsafe 属性（`export_name` / `link_section` / `no_mangle`）、static mut 引用默认 deny、`set_var` / `remove_var` / `before_exec` 转 unsafe 函数。

这是一条清晰的策略线：**Rust 的安全模型不是「把所有东西变安全」，而是「默认安全 + 危险必须显式」**。对照 C++ 的演进方向（智能指针、constexpr、`std::optional`——把更多东西变安全），Rust 2024 反向操作：把过去「隐式危险」的角落（extern 块、static mut、进程环境变量）全部显式化。这会带来真实迁移成本——存量 FFI 代码要补 `unsafe` 块，但这正是「让审查者知道危险在哪里」的价值。注意：`cargo fix` 会保守地帮你补 `unsafe` 块，但它不替你判断「这个 unsafe 是否真的安全」——迁移工具保行为，不保安全。

## 五、独立分析 3：async closures 是异步借用缺口的最后一课

`|| async {}` 与 `async ||` 的差异被官方博文一句话带过，但这正是 Rust 异步模型补课的收尾：

- `|| async {}` 返回的 future 无法借用闭包捕获（借用会逃逸闭包返回值），跨 `await` 持有捕获必然报生命周期错；
- `async ||` 的 future 直接借用捕获，等价于「能捕获环境的 async fn」；
- HRTB 场景：`for<'a> Fn(&'a u8) -> Fut` 无法表达「future 的生命周期依赖输入引用」，`AsyncFn` 一等支持。

`Fn` 家族 2015 年定型，async/await 2021 年落地，「闭包 × 借用 × await」三角直到 2025 年 1.85 才正交。这也是为什么很多 async 生态代码要绕 `Arc<Mutex<..>>` 或 move 进 future 再借出——现在编译器能直接表达这种借用。

## 六、结论与开放问题

结论：值得收录。1.85 表面是例行版本，实则是 2024 版次语义收紧 + async 借用补课的交付节点；归档标签应为「版次语义演进」，而非采集器误标的「Move 语义」。

开放问题：

1. edition 约三年一拍会不会成为「语义债务银行」？临时作用域、drop 顺序这类运行时语义变更逐年累积，`cargo fix` 能否永远兜住迁移？
2. unsafe 收缩推进到 FFI 生态时的摩擦：extern 块、static mut 显式化之后，「默认 unsafe 的老生态」与「显式 unsafe 的新规则」会不会形成维护分层？
3. RPIT 生命周期捕获规则落地后，borrow checker 的剩余缺口（NLL 未覆盖场景、Polonius）何时进 stable？

## 七、最小可运行示例（Rust >= 1.85）

### async closure：借用捕获跨 await（1.85 稳定，无需 edition 2024）

```rust
use std::future::ready;

fn main() {
    let mut logs: Vec<String> = vec![];
    let push = async || {
        // logs 的借用跨 await 成立——1.85 之前等价位 `|| async { .. }` 报：
        //   borrowed data escapes outside of closure
        logs.push(ready(String::from("ok")).await);
    };
    // 在 async 运行时中 push().await 即可；此处仅展示捕获形态
    let _ = push;
}
```

### 元组 collect 扇出（1.85 扩展到 1–12 元，无 panic 路径）

```rust
// rustc 1.85+；直接 rustc 运行即可
use std::collections::{LinkedList, VecDeque};

fn main() {
    let (squares, cubes, tesseracts): (Vec<_>, VecDeque<_>, LinkedList<_>) =
        (0i32..10).map(|i| (i * i, i.pow(3), i.pow(4))).collect();
    println!("{squares:?}");
    println!("{cubes:?}");
    println!("{tesseracts:?}");
}
```
